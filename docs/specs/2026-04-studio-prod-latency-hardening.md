# 图片工作室生产环境卡顿治理

## 背景

2026-04-22 的线上排查表明，生产站图片工作室存在两类直接影响用户体验的问题：

1. 打开任务弹窗后，前端会自动、持续请求 `/api/studio/preview-payload`，而该接口会同步读取远程参考图，导致线上链路放大为 `520/524`。
2. `POST /api/studio/{task_id}/generate` 名义上是“立即返回 + 后台执行”，但实际返回前仍会同步执行 `wan2.7` 参考图探测，导致用户点击“开始生成”时长时间无反馈。

## 目标

- 普通用户打开图片工作室任务弹窗时，不再因开发者模式预览请求拖慢页面。
- 点击“开始生成”后，接口应快速返回 `generating` 状态，前端立即进入提交中/生成中反馈。
- 保留现有工作室能力、参数语义和后台生成链路，不引入新的模型分支。

## 非目标

- 不在本轮重构整个图片工作室页面结构。
- 不在本轮彻底重写 `/api/studio/preview-payload` 的全部校验策略。
- 不通过 Cloudflare 配置替代应用侧修复。

## 方案

### 1. 前端：开发者模式预览按需触发

- `preview-payload` 只在任务弹窗已打开且“开发者模式”展开时触发。
- 预览请求增加取消/去重，仅保留最后一次有效请求结果，避免旧请求覆盖新状态。
- 关闭弹窗或收起开发者模式时，不再继续发起预览请求。

### 2. 后端：`/generate` 真正异步化

- `POST /api/studio/{task_id}/generate` 保留本地、廉价校验：
  - 任务存在
  - 模型/任务类型兼容性
  - 本地可判断的参考图缺失
  - 自定义尺寸等纯参数校验
- 接口返回前不再执行远程参考图读取/探测。
- 接口先把任务更新为 `generating`、清空旧结果、记录当前请求参数快照并立即返回。
- 远程参考图探测、`wan2.7` bbox 归一化、最终 payload 构建和真实生成全部移入后台任务。
- 后台任务若在探测/构建阶段失败，统一把任务写为 `failed` 并落错误信息，前端轮询后即可感知。

### 3. 兼容性

- 保持现有轮询机制不变，前端仍通过 `GET /api/studio/{task_id}` 获取最终状态。
- 生成接口返回结构仍为 `{ "task": ... }`，避免改动调用方协议。
- `provider_payload_snapshot` 允许先写入“提交时快照”，后台生成前再覆盖为最终快照。
- 对同一任务重复点击“开始生成/重新生成”时，后端应返回当前 `generating` 任务而不是重复调度后台任务。

## 验收标准

- 打开图片工作室任务弹窗但不展开开发者模式时，不会触发 `/api/studio/preview-payload`。
- 对带参考图的 `wan2.7-image` 任务调用 `/generate` 时，即使远程图片探测很慢，也能快速返回 `200` 且 `task.status == "generating"`。
- 对同一任务连续重复调用 `/generate` 时，只会调度一次后台任务。
- 后台任务仍能在后续轮询中把任务推进到 `completed` 或 `failed`。
- 相关后端 pytest 通过；前端至少完成 `typecheck` 验证。

## 验证

- `backend/tests/test_studio_capabilities.py`
- `cd frontend && npm run typecheck`
- 人工回归：
  - 打开任务弹窗，不展开开发者模式
  - 展开开发者模式后观察预览请求
  - 点击开始生成，确认立即反馈
