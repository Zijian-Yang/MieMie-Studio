# 图片工作室 OSS 暂存与回退策略

## 背景

- 线上图片工作室仍有部分模型分支会把 DashScope 的临时结果链接直接写入任务结果。
- 临时链接会过期，导致任务详情、图库保存和后续引用出现失效图片。
- 现有上传逻辑分散在多个服务/路由分支内，失败时常常静默回退到原始 URL，缺乏统一告警。

## 目标

- 图片工作室在写入最终任务结果前，统一执行“先落本地暂存，再上传当前用户 OSS”的持久化流程。
- 对瞬时网络抖动、厂商临时链接下载超时、OSS 5xx 等问题做自动重试。
- 重试后仍失败时，临时回退为本地静态文件 URL，并向前端返回明确告警。
- 仅在当前用户已开启 OSS 且具备可用上传链路时启用本地暂存回退，避免把服务器本地存储当长期图床滥用。

## 非目标

- 不修改图库、角色/场景/道具页的历史图片数据迁移策略。
- 不在本次改动中引入后台补偿队列或离线清理任务。

## 方案

### 1. 统一持久化入口

- 图片工作室路由在生成完成后、写入 `StudioTask.images` 前，统一调用 OSS 服务做结果持久化。
- 若某模型分支已经成功返回当前用户 OSS URL，则直接跳过。
- 若返回的是 DashScope/厂商临时签名 URL，则进入统一持久化流程。

### 2. 暂存与上传顺序

- 对每个需要转存的结果图：
  - 下载并写入 `backend/data/assets/oss_staging/...`
  - `flush + fsync`
  - 用该本地文件上传 OSS
  - OSS 上传成功后立即删除本地暂存文件

### 3. 重试与回退

- OSS 上传采用有限次自动重试与指数退避。
- 若失败属于明显不可恢复问题（如 `HTTP 403/404`、鉴权失败、Bucket 不存在），直接判定为失败并清理本地暂存，不保留本地回退。
- 若失败属于持续性但可能恢复的问题（如超时、网络抖动、服务端异常），在重试耗尽后保留本地暂存文件，并把图片 URL 回退为 `/assets/...`。

### 4. 前端告警

- `StudioTask` 新增 `warnings` 字段，承载非阻塞告警。
- `StudioTaskImage` 新增 `storage_source` / `storage_warning`，用于区分 `oss`、`local_fallback`、`remote`。
- 图片工作室任务完成且包含本地回退时：
  - 轮询完成时弹出 warning 提示
  - 浏览器通知正文包含“含警告”
  - 结果详情顶部显示 warning Alert
  - 单张图片打上“本地回退”标记

## 验收标准

- 图片工作室所有模型分支写入最终结果前都经过统一持久化入口。
- 当厂商返回临时 URL 且 OSS 上传成功时，最终保存的是当前用户 OSS URL，本地暂存文件被删除。
- 当厂商返回临时 URL 且上传出现连续瞬时失败时，最终保存的是 `/assets/...` 本地 URL，并返回 warning。
- 当 OSS 明显不可用或无权限时，不保留本地回退文件，任务返回明确失败信息。
- 前端能在任务完成时对本地回退结果给出可见警告。

## 验证

- 后端单测覆盖：
  - 暂存文件在重试成功后被删除
  - 重试耗尽后回退本地 URL
  - 非可恢复 OSS 失败不会保留本地暂存
  - 图片工作室结果会写入 `warnings` 与 `storage_source`
- 手工验证：
  - 真实模型生成一组图片
  - 模拟 OSS 短时失败时能看到本地回退与 warning
