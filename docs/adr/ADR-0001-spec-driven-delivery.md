# ADR-0001：采用 Spec-Driven 文档与交付治理

- **状态**：Accepted
- **日期**：2026-04-16

## 背景

平台已从单一模型/单一路径应用，演化为多工作室、多模型、多厂商、多快照、多兼容层并存的系统。

当前主要问题：

- 功能逻辑可运行，但规范入口不统一
- 厂商镜像文档、实现、页面分支和历史说明并存
- 不同 AI 没有共享记忆时，接手成本高且容易重复造规则

## 决策

采用以下文档分层：

- `AGENTS.md`：仓库级硬约束与快速入口
- `docs/specs/`：功能规格与验收标准
- `docs/adr/`：架构决策与迁移策略
- `docs/checklists/`：门禁与交付清单
- `docs/playbooks/`：可执行操作手册
- `docs/reviews/`：阶段性审计与 backlog

并规定：

1. 非微小改动必须同步更新代码、验证证据和文档
2. 架构/能力变化必须补 spec，必要时补 ADR
3. 供应商镜像文档不直接作为平台规范

## 结果

### 正面

- 新 AI 可通过文档而非聊天历史接手
- 评审与验收有共同结构
- 规范与实现漂移更容易暴露

### 负面

- 文档维护成本上升
- 需要持续清理 legacy 文档，不能只新增不收敛

## 后续约束

- 新模型接入必须走 spec → adapter/schema → 验证 → 文档更新
- 对旧文档的更新要优先做“纠偏”，不是继续复制历史路径
